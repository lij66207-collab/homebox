# AGENTS.md

Guidance for AI coding agents working in this repository. This file assumes no prior knowledge of the project.

## Project Overview

**Homebox** is a self-hosted home inventory, organization, and management system (repo: `sysadminsmedia/homebox`). It is a monorepo with three main components:

| Directory  | Description |
|------------|-------------|
| `backend/` | Go REST API server (the actual application; embeds the frontend at build time) |
| `frontend/` | Nuxt 4 / Vue 3 single-page application (statically generated, served by the Go binary) |
| `docs/` | Astro + Starlight documentation site (deployed to Cloudflare, see `wrangler.jsonc`) |

Design principles (from the README): simple but expandable, blazingly fast (Go, <50MB idle memory), portable (SQLite by default, embedded Web UI, single container).

Key configuration files:

- `Taskfile.yml` — the central task runner; all common dev/CI commands live here. Run `task --list-all` to see everything.
- `backend/go.mod` — Go module `github.com/sysadminsmedia/homebox/backend`, Go 1.26.
- `backend/.golangci.yml` — lint rules (golangci-lint v2 config format).
- `frontend/package.json` — pnpm workspace (`pnpm@10.28.0` pinned via `packageManager`), Nuxt 4, Vitest, Playwright.
- `frontend/nuxt.config.ts`, `frontend/eslint.config.mjs`, `frontend/tailwind.config.js` — frontend build/lint config.
- `docs/package.json` — docs site (pnpm, Astro 6).
- `Dockerfile`, `Dockerfile.rootless`, `Dockerfile.hardened` — production images (multi-stage: pnpm frontend build → Go build with embedded static assets → Alpine runtime).
- `backend/.goreleaser.*.yaml` — release binary builds.
- `.github/workflows/` — CI (see "CI & Release" below).
- `.devcontainer/` — VS Code devcontainer that runs `task setup` on create.

## Technology Stack

### Backend (`backend/`)

- **Language**: Go 1.26, module root is `backend/` (not the repo root).
- **HTTP**: `go-chi/chi/v5` router (`backend/app/api/routes.go`), `hay-kot/httpkit` for error chains/graceful shutdown.
- **Database**: SQLite (default, CGO-free via `modernc.org/sqlite` wrapped in `backend/pkgs/cgofreesqlite`) or PostgreSQL (`jackc/pgx/v5`). Selected via `HBOX_DATABASE_DRIVER`.
- **ORM**: Entgo (`entgo.io/ent`). Schemas in `backend/internal/data/ent/schema/`; everything else under `backend/internal/data/ent/` is **generated code — do not edit**.
- **Migrations**: goose, SQL files in `backend/internal/data/migrations/sqlite3/` and `.../postgres/` (registered via blank imports in `main.go`). Both dialects must be kept in sync.
- **API docs**: Swaggo annotations on handlers; `swag init` produces `backend/app/api/static/docs/swagger.json`, converted to OpenAPI 3 and copied into `docs/public/api/`.
- **Observability**: OpenTelemetry (traces/metrics/logs, OTLP exporters) in `backend/internal/sys/otel`; `zerolog` for logging.
- **Config**: `ardanlabs/conf/v3`, environment variables prefixed `HBOX_` (e.g. `HBOX_DATABASE_DRIVER`, `HBOX_WEB_PORT`). Defaults for dev are set at the top of `Taskfile.yml`.
- **Other**: OIDC auth (`coreos/go-oidc`), websockets (`olahol/melody`), pub/sub event bus via `gocloud.dev/pubsub` (in-mem, NATS, Kafka, RabbitMQ, SQS...), notifier webhooks via `shoutrrr`, image transcoding (webp/avif/heic/jxl — requires system libs on some arches, hence the `nodynamic` build tag), QR code generation, `blake3` hashing.

### Frontend (`frontend/`)

- **Framework**: Nuxt 4 (Vue 3, TypeScript), statically generated via `nuxt generate` (`pnpm build`). In dev, `/api` is proxied to `http://localhost:7745/api` (see `nuxt.config.ts`).
- **Styling**: Tailwind CSS 3 + shadcn-vue (`components/ui/` is generated by shadcn and **excluded from ESLint** via `--ignore-pattern "components/ui"`).
- **State**: Pinia (`stores/`). i18n via vue-i18n with JSON locales in `locales/` (translations are managed through Weblate — do not hand-edit non-English locale files unless asked).
- **API client**: hand-written client classes in `frontend/lib/api/classes/` built on generated types in `frontend/lib/api/types/` (**generated from the Go swagger spec — do not edit manually**).
- **Icons**: lucide-vue-next, unplugin-icons, @iconify.
- PWA support via `@vite-pwa/nuxt`; client-side OpenTelemetry tracing in `lib/otel/`.

### Docs (`docs/`)

Astro 6 + Starlight, Tailwind 4, deployed with Wrangler to Cloudflare. Dev: `pnpm dev`, build: `pnpm build` inside `docs/`.

## Repository Layout

## Build, Dev & Code Generation Commands

All commands are Task tasks (install [Task](https://taskfile.dev)); run from the repo root unless noted.

- `task setup` — install dev tools (`swag`, `goose`) and all Go/pnpm dependencies.
- `task go:run` — run the API server locally (SQLite in `.data/`, port **7745**, demo mode). The server does **not** auto-reload.
- `task go:run:postgresql` — same, against a local Postgres (expects `homebox/homebox` on localhost:5432).
- `task ui:dev` — Nuxt dev server (proxies `/api` to the backend on 7745).
- `task go:build` — build the backend binary to `build/backend`.
- `task pr` — full local pre-PR pipeline: `generate` → `go:all` (tidy, lint, test) → `ui:check` → `ui:fix` → `test:ci`.

### Code generation (important!)

Several artifacts are generated and checked in. After changing any of their sources, regenerate:

1. **Ent code** — after editing `backend/internal/data/ent/schema/`: `task db:generate` (runs `go generate ./...` in `backend/internal/`, invoking `ent generate`).
2. **Swagger docs** — after changing API handlers or repo/service types: `task swag` (needs `swag` installed; regenerates swagger.json + OpenAPI 3 in `backend/app/api/static/docs/` and copies to `docs/public/api/`).
3. **TypeScript types** — after swagger changes: `task typescript-types` (swagger-typescript-api into `frontend/lib/api/types/`, then `app/tools/typegen` post-processing).
4. `task generate` runs all of the above (db:generate → swag → typescript-types).

Do not hand-edit: `backend/internal/data/ent/**` (except `schema/`), `backend/app/api/static/docs/**`, `frontend/lib/api/types/**`, `frontend/components/ui/**`.

## Testing

- **Backend unit/integration tests**: `task go:test` (`go test ./...` in `backend/`). Tests use `stretchr/testify` and live next to the code (`*_test.go`). Repo-layer tests use a shared setup in `main_test.go` files and run against an in-memory/temp SQLite database.
  - Coverage with race detector: `task go:coverage`.
- **Frontend API tests (Vitest)**: `task ui:watch` / `pnpm test:local` / `pnpm test:ci` inside `frontend/`. Config: `frontend/test/vitest.config.ts` (includes `**/*.test.ts`, e.g. `frontend/lib/api/__test__/`). **These tests require a running API server** (see CONTRIBUTING: first run can fail on a race — rerun). `test:ci` sets `TEST_SHUTDOWN_API_SERVER=true` to kill the `api` process afterwards.
- **E2E tests (Playwright)**: `task test:e2e` — builds backend + frontend, serves the app on :7745, runs `frontend/test/e2e/*.browser.spec.ts` across Chromium/Firefox/WebKit (`frontend/test/playwright.config.ts`).
- **CI-mode combined test**: `task test:ci` (SQLite) and `task test:ci:postgresql` build the API, start it, and run the Vitest suite against it.

Convention (from CONTRIBUTING.md): **unit tests are written in Go; end-to-end / user-story tests are written in TypeScript** using the client library in `frontend/lib/api`.

## Code Style & Linting

### Go

- `task go:lint` → `golangci-lint run ./...` in `backend/` (CI uses `--timeout=6m`). Enabled linters include `errcheck`, `errorlint`, `staticcheck`, `govet`, `revive`, `gocritic`, `gocyclo`, `testifylint` (all checks), `zerologlint`, `depguard`, `forbidigo` (forbids `log.Fatal` — return errors instead), `tagalign` (struct tag order: `json`, `schema`, `yaml`, `validate`). Formatters: `gofmt` + `swaggo`.
- Generated Ent code is excluded from linting.
- Run `task go:tidy` after changing dependencies.

### Frontend / TypeScript

- `task ui:fix` → ESLint (`--fix`) with Prettier integration (`eslint-plugin-prettier`), `eslint-plugin-tailwindcss`, and the Nuxt ESLint config (`frontend/eslint.config.mjs`). `components/ui` is ignored.
- `task ui:check` → `nuxi typecheck --noEmit` (vue-tsc).
- CI enforces `--max-warnings 1` (`pnpm lint:ci`).
- Prettier defaults apply (2-space indent, double quotes, semicolons, trailing commas).

### Commits / PRs

- PRs target `main` from feature branches (see `CONTRIBUTING.md`). Add tests for new code; update docs when APIs change; ensure tests and linters pass before opening a PR.

## CI & Release

- **PR CI** (`.github/workflows/pull-requests.yaml`): runs on changes to `backend/` or `frontend/`:
  - `partial-backend.yaml`: golangci-lint, `task go:build`, `task go:coverage` (Go 1.26).
  - `partial-frontend.yaml`: frontend lint/typecheck/tests.
  - `e2e-partial.yaml`: Playwright e2e.
  - `upgrade-test.yaml`: upgrade-path verification (`frontend/test/upgrade/`).
- **Releases**: create a GitHub tag `vX.X.X` → tests → GoReleaser binaries (`backend/.goreleaser*.yaml`, amd64/arm64/riscv64) → release publish → Docker image builds (`docker-publish*.yaml`: standard, rootless, hardened — signed with cosign, keys in `backend/`) → docs deploy + Fly.io demo.
- **Production deployment**: single Docker image (`ghcr.io/sysadminsmedia/homebox`), port **7745**, data volume `/data` (SQLite DB + attachments). Rootless/hardened variants run as UID 65532. Healthcheck: `GET /api/v1/status`.

## Security Considerations

- `HBOX_AUTH_API_KEY_PEPPER` must be ≥32 bytes at startup (the server refuses to boot otherwise); API keys are stored as HMAC/blake3 hashes (`backend/pkgs/hasher`). Rotating the pepper invalidates all issued API keys.
- Password reset CLI subcommand: `api reset-password` (handled before config load in `main.go`).
- HTTP hardening: security headers middleware (`internal/web/mid`), per-path max body size, rate limiting, and `middleware.RealIP` is deliberately NOT used — client IPs come from `extractClientIP` honoring an explicit trust-proxy gate.
- Outbound notifier webhooks (shoutrrr) are guarded against SSRF, including a redirect guard installed on `http.DefaultClient` (`internal/sys/validate`).
- `backend/cosign.key` / `cosign.pub` are the release signing keys — never expose or modify the private key.
- Don't commit secrets; config is env-driven (`HBOX_*`) or a YAML config file path passed as the first CLI arg.

## Common Pitfalls for Agents

- The Go module root is `backend/`, not the repo root — run `go`/`golangci-lint` from there (Task tasks handle this).
- API shape changes require the full codegen chain (`task generate`) or the frontend types will drift.
- Both SQLite and Postgres migrations must be added for schema changes.
- Frontend Vitest tests are integration tests against a live server on :7745, not pure unit tests.
- English locale (`frontend/locales/en.json`) is the source of truth; other languages are managed via Weblate.
